Fila 0.6.9 fixes more than a hundred problems found in a review of the whole app, and makes copies, saves and links behave the way they say they do.

- Copying a folder on the same volume keeps the access control lists and setuid bits of everything inside it. Each file is still a clone that takes no extra space.
- Saving a file now gives it a new modification time, so sync, backup and build tools see the edit. Saving through a symbolic link saves the file it points to and leaves the link in place.
- A `fila://open` link to a file opens its folder with the file selected, in a new tab too with `tab=new`, and a link that launches Fila is no longer lost while it connects.
- Locked, Append Only, Hidden and No Dump in Edit Flags are applied again. Before this release, Apply left the flags unchanged.
- Cancelling a copy of several items reports it as cancelled, not as a failure.
- An extraction that leaves members out says how many, instead of reporting a plain success.
- Long copies keep going while Fila is in the background, and a package installation can no longer be interrupted by tapping the sidebar or the path bar.
- Archives, WebDAV and recursive permission changes are held to the folder they were given, even against links and names built to escape it.

Choose the RootHide or the rootless Debian package for a jailbroken device, the TrollStore TIPA for TrollStore, or the standard IPA to sideload. SHA-256 checksums are in `SHA256SUMS`.
